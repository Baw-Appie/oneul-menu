# 최근 7일 선택 기록 요약

2026-10-27. PRD F12, Todo 7-4의 독립 모듈 구현 및 검증 기록이다. 프로젝트의 `AGENTS.md`와 `skills/meal-picker-review/SKILL.md`를 적용했다.

## 담당 파일과 통합 계약

- `src/history-summary.mjs`: `data.mjs`만 가져온다. `core.mjs`, 저장소, 서버, 전역 DOM에 의존하지 않는다.
- `src/history-summary.css`: 모든 선택자를 `history-summary` 접두사로 한정했다. 기존 디자인 변수를 사용하며 600px 이하에서 세부 정보를 한 열로 배치한다.
- `docs/HISTORY_SUMMARY.md`: 이 기능의 계약, 실제 검증과 한계를 기록한다.

`summarizeHistory(history, now = new Date())`는 입력을 변경하지 않고 다음 객체를 반환한다.

```js
{
  totalChoices: 1,
  uniqueMenus: 1,
  activeDays: 1,
  topCategories: [{ name: "한식", count: 1 }],
  recentChoices: [{ menuId: "bibimbap", date: "2026-10-27" }],
}
```

위 값은 구조 설명용이다. 빈 기록은 숫자 0과 빈 배열을 반환한다. 오늘과 이전 6일을 로컬 달력 기준으로 포함하며, 밀리초를 24시간으로 나누거나 UTC 날짜 문자열을 잘라 계산하지 않는다. 로컬 정오에서 6일 전 달력 날짜를 계산해 일반적인 일광 절약 시간 전환의 영향을 피한다.

- 알려진 메뉴 ID와 실제 달력 날짜인 `YYYY-MM-DD`만 집계한다. 기존 기록 검증과 같이 연도는 2000년 이상이다.
- 미래, 기간 이전, 없는 메뉴, 잘못된 날짜와 같은 날짜·메뉴 ID 중복은 제외한다. 중복은 원본에서 처음 나타난 한 건만 남긴다.
- `recentChoices`는 유효한 기간 내 기록 전체다. 날짜 내림차순으로 정렬하며 같은 날짜의 원래 입력 순서를 유지한다.
- `topCategories`는 공동 최다 선택 종류를 모두 반환한다. 순서는 `data.mjs`의 `categories` 순서이며 기록 배열의 순서에 따라 달라지지 않는다.
- 배열이 아닌 기록이나 유효하지 않은 `now`는 빈 요약을 반환한다.
- 이 순수 함수는 입력 배열을 저장하거나 자르지 않는다. 앱의 기존 저장·복원 로직이 기록을 최대 30건으로 제한하고, 이 함수는 전달받은 기록의 최근 7일을 집계한다.

`renderHistorySummary(container, history, now = new Date())`는 DOM 요소인 `container`의 자식만 교체하고 같은 요약 객체를 반환한다. 다른 요소나 저장 상태는 변경하지 않는다. 모든 동적 표시 문자열은 `textContent`로 넣는다. 메뉴 날짜는 `<time datetime="YYYY-MM-DD">`로 제공한다.

```js
import { renderHistorySummary } from "./history-summary.mjs";

renderHistorySummary(
  document.querySelector("#history-summary"),
  state.history,
);
```

부모 통합에서는 `src/history-summary.css`를 연결하고 기록 목록 위에 `#history-summary` 요소를 둔다. 초기 복원, 메뉴 확정, 기록 삭제, 로컬 날짜 변경 시 렌더러를 다시 호출한다. 모듈은 이벤트 리스너나 날짜 갱신 타이머를 직접 만들지 않는다.

표시 제목은 ‘나의 한 주 메뉴’다. 선택 횟수·서로 다른 메뉴·기록한 날짜를 설명 목록으로 표시하며, 공동 1위 종류와 최근 최대 7건의 메뉴 이름·날짜를 제공한다. 빈 기록에는 메뉴 확정을 안내한다. 항상 ‘이 브라우저에 저장된 최근 7일 기록 기준’과 최대 30건 보관으로 일부 기록이 빠질 수 있다는 안내를 표시한다. 실제 식사 여부, 영양과 지출을 추정하지 않는다.

## 검증과 한계

실제 실행한 검증:

- `node --check src/history-summary.mjs` 통과.
- Node 내장 `node:assert/strict`를 사용하는 stdin 검증 19개 그룹 통과. 테스트 파일과 패키지를 추가하지 않았다.
- 로직 10개 그룹: 빈 값·잘못된 입력, 오늘/6일 전 포함과 7일 전/미래 제외, 같은 날짜·ID 중복 제거와 다른 날짜의 같은 메뉴 집계, 엄격한 날짜·알려진 ID 검증, 같은 날짜의 안정 정렬·입력 불변성·반환 객체 분리, 여섯 종류 공동 1위의 고정 순서, 월말·연말, 윤년과 2100년의 비윤년, 7일간 35건을 전달한 순수 집계와 고유 메뉴·날짜 수, 빈 결과 배열의 독립성을 확인했다. 35건 검증은 순수 함수가 임의로 입력을 자르지 않는 계약을 확인하며 앱 저장 한도가 늘어났다는 뜻은 아니다.
- 렌더링 3개 그룹: 메모리 DOM 대역으로 제목·설명 목록·최대 7건·`time.dateTime`·공동 1위·보관 안내, 빈 기록으로 재렌더할 때 이전 내용 제거, HTML 형태 메뉴 이름을 그대로 텍스트로 표시하는 것을 확인했다. DOM 대역은 `innerHTML` 대입 시 실패하도록 만들어 렌더러에서 HTML 파싱 경로를 사용하지 않는 것도 확인했다.
- 날짜 추가 6개 그룹: `Asia/Seoul`, `America/Los_Angeles`, `Pacific/Kiritimati` 각각의 로컬 자정 직후·늦은 밤 경계, 로스앤젤레스 2026년 봄·가을 DST 전환을 포함하는 기간, 기본 `now` 인수를 확인했다.

CSS는 폭을 고정하지 않고 `minmax(0, 1fr)`, 줄바꿈과 모바일 한 열 세부 배치를 사용했다. 스타일 선택자는 모두 `.history-summary` 접두사에 한정했다. 실제 브라우저 및 스크린 리더에서 이 구성의 표시·읽기 순서를 확인하지는 않았다.

공통 파일 통합과 실제 브라우저의 선택·확정·새로고침·삭제·날짜 변경, 375px 가로 넘침 및 보조 기술 확인은 부모 채팅의 통합 검증 범위다. 통합 검증이 수행되었다고 이 문서에서 주장하지 않는다.
