# 즐겨찾기 모듈

작성일: 2026-10-27 (Asia/Seoul)

## 범위와 제품 규칙

사용자가 요청한 즐겨찾기 기능의 순수 로직과 카드 버튼을 구현한다. 기존 PRD의 F1(메뉴 카드), F2(조건 결합), F3(같은 후보에서 추천), F5(저장 복원), F6(접근성과 모바일)에 연결된다. 공통 PRD·Todo의 신규 기능 항목과 전체 앱 연결은 통합 채팅에서 반영한다.

`skills/meal-picker-review/SKILL.md`를 적용했다. 저장값의 알려진 메뉴 ID·중복·목록 크기를 검증하고, 기존 조건 결과에 즐겨찾기를 AND로 적용한다. 이 모듈은 상태, 저장소, DOM, AI 요청, 선택 기록을 직접 변경하지 않는다.

## 내보내기와 통합 계약

`src/favorites.mjs`는 `src/data.mjs`의 `menus`만 가져오며 다음 네 함수를 내보낸다.

| 함수 | 입력과 반환 계약 |
| --- | --- |
| `normalizeFavorites(value)` | 배열이 아니면 새 빈 배열. 현재 메뉴 데이터에 있는 ID만 최초 등장 순서로 중복 없이 새 배열에 담는다. 최대 길이는 현재 메뉴 수다. 원본을 변경하지 않는다. |
| `toggleFavorite(favorites, menuId)` | 먼저 즐겨찾기를 정규화하고, 알려진 ID이면 추가하거나 제거한 새 배열을 반환한다. 추가한 ID는 마지막에 온다. 알 수 없는 ID이면 정규화한 새 배열만 반환한다. |
| `filterFavorites(candidates, favorites, onlyFavorites)` | `onlyFavorites === true`이면 즐겨찾기 ID가 있는 후보만 후보 순서와 객체를 유지해 새 배열로 반환한다. 그 외에는 입력 후보 배열을 그대로 반환한다. `candidates`는 기존 필터가 반환하는 메뉴 객체 배열이다. |
| `favoriteButtonMarkup(menu, isFavorite)` | 알려진 `menu.id`의 정적 데이터로 하트 버튼 HTML을 반환한다. 알 수 없는 메뉴는 빈 문자열. `isFavorite === true`일 때만 선택 상태다. 전달된 객체의 이름 대신 정적 메뉴명을 사용하며 속성값도 HTML 이스케이프한다. |

버튼은 `type="button"`, `data-favorite="메뉴 ID"`, `aria-pressed="true/false"`, `aria-label="메뉴명 즐겨찾기 추가/해제"`를 가진다. 기본 클래스는 `favorite-button`, 선택 시 `is-favorite`가 추가된다. 장식 SVG는 보조기기에서 숨기며, 하트 윤곽과 채움으로 상태를 구분한다.

통합 시 `src/favorites.css`를 기존 스타일 뒤에 불러오고 `favoriteButtonMarkup(menu, state.favorites.includes(menu.id))`를 `.card-art`의 자식으로 삽입한다. 버튼은 카드 오른쪽 아래에 배치한다. 오른쪽 위 제외 버튼과 왼쪽 위 음식 종류 배지를 피하며, 모든 화면에서 44 × 44px 터치 영역과 키보드 포커스 표시를 유지한다. 700px 이하에서는 가장자리 간격만 7px로 줄인다. CSS 선택자는 즐겨찾기 버튼 클래스에만 적용한다.

통합 채팅이 다음 항목을 담당한다.

- `state.favorites`의 초기화·저장·복원 및 `filters.onlyFavorites`의 boolean 검증.
- 전체/즐겨찾기만 전환 UI와 전체 즐겨찾기 수. 다른 조건 때문에 숨겨진 즐겨찾기를 저장 목록에서 삭제하지 않는다.
- 기존 필터 결과에 `filterFavorites`를 적용해 카드·추천·AI에 같은 후보 집합 제공.
- `event.target.closest("[data-favorite]")`를 통한 위임 클릭, 저장, 재렌더링, 포커스 복원.
- 즐겨찾기 후보가 바뀔 때 진행 중인 AI 검색 취소 및 이전 응답 무시.
