# 메뉴 대결

작성일: 2026-10-27. 현재 필터와 자연어 검색 결과에 들어 있는 메뉴 두 개를 비교하고 하나를 기존 결과 대화상자로 넘기는 기능이다.

## 제품 규칙

- 후보는 부모 앱의 `getCandidates()` 반환값만 사용한다. 메뉴 ID가 중복되면 처음 나온 객체를 사용한다.
- 후보 0개면 시작 버튼을 비활성화한다. 이미 열린 대결창에는 조건 조정 안내를 표시한다.
- 후보 1개면 한 카드와 안내를 표시한다. 2개면 두 카드를 표시하며, 다른 조합이 없으므로 다시 뽑기 버튼을 비활성화한다.
- 후보가 3개 이상이면 다른 후보 보기에서 직전 두 메뉴와 다른 조합을 무작위로 고른다. 한 메뉴는 다시 등장할 수 있다.
- 고르기 직전에 후보를 다시 읽는다. 조건 변경으로 제외된 메뉴는 결과 대화상자로 넘기지 않는다.
- 대결 열기·닫기·다시 뽑기·고르기에서는 저장과 기록 변경을 하지 않는다. 기존 결과 대화상자의 확정 흐름에서 기록한다.
- 프로젝트 PRD의 F2·F3·F4·F6·F7 후보 일관성, 확정 시 기록, 키보드 사용 규칙을 적용한다. 공통 PRD·Todo의 신규 번호와 통합 검증은 부모 채팅에서 기록한다.

## 파일과 통합 계약

- `src/menu-duel.mjs`: 아래 두 함수를 named export한다. 모듈 평가 시 `document`에 접근하지 않아 순수 함수는 Node에서 import할 수 있다.
- `src/menu-duel.css`: 기존 `styles.css` 뒤에 불러온다. 모든 선택자는 `#menu-duel-dialog` 안에 한정되며 기존 색상 변수, 메뉴 색상 클래스, `.primary-button`, `.secondary-button`, `.icon-button`을 사용한다.
- 서버의 정적 파일 허용 목록에 `src/menu-duel.css`를 추가해야 한다. 이 문서와 모듈은 공통 파일을 수정하지 않는다.

```js
import { setupMenuDuel } from "./menu-duel.mjs";

const menuDuel = setupMenuDuel({
  trigger: document.querySelector("#menu-duel"),
  getCandidates,
  onChoose: showMenu,
  notify,
});
```

`trigger`는 부모가 만들고 배치한 `HTMLButtonElement`다. `getCandidates()`는 현재 필터·제외·AI 결과를 모두 적용한 메뉴 객체 배열을 동기적으로 반환한다. 객체는 기존 데이터의 `id`, `name`, `category`, `price`, `spice`, `emoji`, `color`, `description` 필드를 갖는다. 문자열 ID는 비어 있지 않고 가격은 원 단위 양의 정수, 매운맛은 0·1·2다.

`onChoose(menu)`는 대결 대화상자를 닫은 후 동기적으로 호출한다. 현재 후보에서 다시 찾은 최신 객체를 전달하므로 부모는 기존 `showMenu`를 연결하면 된다. 이 콜백에 기록 추가를 연결하지 않는다. `notify(message)`는 오래된 선택이나 빈 후보 안내를 부모 토스트로 표시한다.

반환값은 `{ refresh(), destroy() }`다.

- 모든 필터·검색·제외·AI 결과 변경 후 `renderMenus()` 같은 공통 렌더 함수에서 `menuDuel?.refresh()`를 호출한다. 초기화가 마지막에 일어난다면 참조는 `let menuDuel`로 먼저 선언한다.
- `refresh()`는 시작 버튼의 disabled 상태를 갱신한다. 열린 대결창에서는 유효한 기존 조합을 유지하되 최신 객체로 카드를 갱신하고, 조합이 무효하면 현재 후보에서 다시 고른다. 선택 중이던 카드가 없어지면 남은 카드 또는 닫기 버튼으로 포커스를 옮긴다.
- `destroy()`는 생성한 대화상자와 이벤트 리스너를 제거하고 시작 버튼의 기존 disabled·ARIA 속성을 복원한다. 두 메서드는 제거 후 다시 호출해도 동작하지 않는다. 같은 문서에서 한 인스턴스만 초기화할 수 있으며 제거 후에는 다시 초기화할 수 있다.
- 모듈은 `body`에 `#menu-duel-dialog` 네이티브 `<dialog>`를 생성한다. 제목·설명 연결, 상태 알림, 명시적 닫기, Escape 기본 동작을 제공한다. 닫은 뒤 다른 대화상자가 열렸다면 시작 버튼으로 포커스를 강제로 이동하지 않는다.

```js
pickMenuPair(candidates, random = Math.random)
```

고유 ID가 0개면 `[]`, 1개면 `[menu]`, 여러 개면 서로 다른 두 객체를 새 배열로 반환한다. 입력 배열과 메뉴 객체는 변경하지 않는다. 균등 난수 생성기를 전달하면 모든 순서 있는 쌍의 확률은 `1 / (n × (n - 1))`이다. `random`은 호출마다 0 이상 1 미만의 유한한 수를 반환해야 하며, 범위 밖 값은 `RangeError`다. 후보가 0·1개면 난수를 호출하지 않는다.

## 검증 기록

2026-10-27, Node.js v24.11.0에서 `node --input-type=module` stdin과 내장 `node:assert/strict`로 검증했다. 테스트 파일과 의존성은 남기지 않았다.

- 순수 함수 6개 검증 그룹 통과: 후보 0·1개에서 난수 미호출, ID 중복 제거와 첫 객체 유지, 입력 불변성과 난수 하한·상한 직전 경계, 후보 2·3·4·5·30개의 모든 순서 쌍을 각 한 번씩 뽑는 결정적 검증, 잘못된 난수 거부, 복합 필터·AI 결과 부분집합 안에서만 추출.
- 모의 DOM 9개 검증 그룹 통과: 0개 비활성화와 초기화 중복 방지, 1개 카드와 취소 시 콜백 미호출, 대결창을 닫은 뒤 결과 콜백 실행 및 다른 열린 대화상자의 포커스 보존, 100회 재추출에서 직전 조합 회피, 새 메뉴 객체와 카드 포커스 갱신, `refresh()` 호출 없이 후보가 바뀐 경우에도 오래된 선택 차단, 열린 상태에서 후보가 0개가 되는 경우, 포커스 중인 재추출 버튼 비활성화 시 닫기로 이동, 제거·중복 제거·재초기화와 트리거 속성 복원.
- `node --check src/menu-duel.mjs`와 담당 파일의 `git diff --check` 통과.

실제 브라우저 렌더링, 네이티브 Escape·Tab 순서·스크린리더 알림, 375px 화면의 잘림·가로 넘침, 서버 CSS 제공, 부모 결과 대화상자의 확정·기록·새로고침·삭제 흐름은 이 채팅에서 수행하지 않았다. 모의 DOM은 로직 검증용이며 브라우저 동작을 증명하지 않는다. 부모 채팅에서 공통 파일에 연결한 뒤 해당 통합 검증을 수행해야 한다.
