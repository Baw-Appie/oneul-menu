# 최근 먹은 메뉴 제외

담당 범위는 `src/recent-meals.mjs`의 순수 로직이다. 기존 PRD F2·F3·F4·F5와 Todo 3-1·3-3·3-4에 연결되는 추가 기능이며, 공통 PRD·Todo와 화면·저장 통합은 부모 채팅에서 반영한다.

## 공개 계약

- `normalizeRecentDays(value)`: 숫자 `3`, `7`만 그대로 반환하고, 숫자 `0` 및 그 밖의 값은 `0`으로 정규화한다. 문자열 `"3"`·`"7"`은 허용하지 않는다.
- `filterRecentMeals(candidates, history, days, now = new Date())`: 후보 메뉴 객체의 `id`와 선택 기록의 `menuId`를 비교한다. 제외 후에도 원래 후보 순서와 객체 참조를 유지하는 새 배열을 반환한다. 입력 배열·기록·`now`는 변경하지 않는다.
- `0`은 비활성화, `3`은 오늘과 이전 2일, `7`은 오늘과 이전 6일이다. 시작일과 오늘을 모두 포함하며, 오늘보다 미래인 날짜는 무시한다.
- 오늘은 `now`의 로컬 연·월·일로 판단한다. 기록 날짜는 실제 달력에 존재하는 `YYYY-MM-DD` 문자열만 허용하며 ISO 시각 문자열·불가능한 날짜·형식이 다른 날짜는 무시한다. 달력 날짜 번호를 비교하므로 로컬 자정의 UTC 날짜 차이, 월·연도 경계, 윤년, DST의 23시간·25시간 하루에 영향을 받지 않는다.
- 기록이 배열이 아니거나 `now`가 유효한 `Date`가 아니면 제외하지 않은 새 후보 배열을 반환한다. 후보가 배열이 아니면 빈 배열을 반환한다. 잘못된 기록 객체·빈 ID·문자열이 아닌 ID는 무시한다. 현재 후보에 없는 ID는 결과에 영향을 주지 않는다.

`core.mjs`나 다른 모듈을 import하지 않으므로 부모가 `core.mjs`에서 import해도 순환 의존성이 없다. 저장은 수행하지 않는다. 기존 `normalizeState`·`addChoice`가 관리하는 최대 30건과 같은 날짜·메뉴 중복 방지 규칙을 그대로 유지한다. 이 함수는 전달받은 기록을 자르거나 정렬하지 않는다.

## 부모 통합 지점

1. `filters.recentDays`를 기본값 `0`으로 추가하고, 복원할 때 `normalizeRecentDays`를 적용한다. UI 문자열은 이벤트 처리에서 숫자로 변환한다.
2. 일반 조건의 후보에 `filterRecentMeals(candidates, state.history, state.filters.recentDays)`를 적용한다. 화면·후보 수·추천·AI에 전달할 후보가 같은 결과를 사용해야 한다.
3. 기록 확정·삭제 또는 기간 변경 시 진행 중 AI 검색을 취소하고 후보를 다시 계산한다. AI 응답은 갱신된 후보의 부분집합이어야 한다.
4. 후보가 0개이면 기간을 `0`으로 되돌리는 해제 버튼을 제공한다. 기록·저장·UI와 자정 이후 후보 갱신은 호출 측의 책임이다. 재평가 시 기본 `now`가 현재 로컬 날짜를 읽는다.

## 검증

2026-10-27, Node.js v24.11.0에서 `node --input-type=module`의 stdin으로 `node:assert/strict` 검증 15개 그룹을 실행했고 모두 통과했다. 임시 테스트 파일은 만들지 않았다.

| 확인 항목 | 실제 결과 |
| --- | --- |
| 숫자 `0`·`3`·`7`, 문자열·소수·음수·NaN·Infinity·객체 등 | 유효한 숫자 기간만 활성화 |
| 서울·UTC·뉴욕·베를린·로드하우·호놀룰루의 로컬 자정 | 3일·7일의 양쪽 경계와 미래 날짜 제외가 기대한 후보와 일치 |
| 자정 직전과 직후, 월말·연말·윤년 2월 29일 | 날짜 변경 시 만료·새 기록 적용, 시작일 포함·그 이전 날 유지 |
| 뉴욕·베를린·로드하우의 DST 시작·종료 전후 | 각 전환을 포함하는 기간의 0시·12시·23시에서 같은 날짜 범위 적용 |
| 불가능한 날짜·시각 문자열·잘못된 기록 객체·중복·알 수 없는 ID | 잘못된 기록과 미래 기록이 후보를 제거하지 않음, 중복 기록 영향 없음 |
| 후보 0개·1개·여러 개, 전체 제외, 잘못된 옵션 | 빈 결과·일부 결과가 정확하며 잘못된 `history`·`now`는 제외 없이 복사 |
| 동결된 후보·기록, 순서·객체 참조·`now` | 입력 변경 없이 순서와 후보 객체 참조를 보존한 새 배열 반환 |
| 기본 `now`, 기존 `normalizeState`·`addChoice`와 함께 확인 | 오늘 기록 기본 적용, 저장 기록 최대 30건 유지, 필터 호출 전후 기록 동일 |

브라우저 UI·저장 복원·AI·추천 통합 검증은 이 담당 작업에서 수행하지 않았다. 이 문서의 통과 결과는 순수 함수와 기존 기록 저장 함수에 대한 Node 검증이며, 실제 모델 호출이나 화면 동작 확인을 의미하지 않는다.
